# remora-control

Software for the biomimetic remora robot — an underwater robot with an articulated,
compliant neck and a biomimetic adhesive disc.

`firmware/` is the robot's onboard software, the control system that runs the machine.
`learning/` trains and evaluates the neck controllers from recorded remora kinematics;
`models/` holds the network deployed to the robot.

## Repository layout

```
firmware/     onboard software for the robot (STM32H743VITx, FreeRTOS, X-CUBE-AI)
learning/     training and analysis pipeline for the neck controllers
  mlp26/      training package
data/
  raw/        motion-capture exports
  processed/  resampled and cleaned training sequences
models/       exported networks deployed to the robot
```

All figures are generated by the commands below.

## Firmware

The onboard software runs the behaviour layer, the motion planner, the low-level
controllers and the servos on an STM32H743VITx under FreeRTOS, together with the
learned neck controller.

| | |
|---|---|
| MCU | STM32H743VITx |
| RTOS | FreeRTOS (CMSIS-RTOS v2) |
| Toolchain | GNU Arm Embedded |
| CubeMX project | `firmware/remorarl43.ioc` |
| X-CUBE-AI | 9.0.0-19802 |

```
cd firmware
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

This produces `build/remorarl43.elf`, `.hex` and `.bin`. `firmware/README.md` describes
the structure of the application code.

STM32 HAL/CMSIS, FreeRTOS and the X-CUBE-AI runtime are not vendored in this repository.
Open `firmware/remorarl43.ioc` in STM32CubeMX with the X-CUBE-AI expansion package to
regenerate them.

## Neck controllers

Attachment and detachment each have their own controller, trained by behaviour cloning
from the recorded remora kinematics. `learning/mlp26` holds the training code for the
six-input controller (disc–surface angle, head height, and their first and second time
derivatives); `learning/` also holds the evaluation and figure scripts.

A separate two-input network, taking only disc angle and head height, is trained on the
same demonstrations for the decision-space figures.

`python -m learning.mlp26 --export` trains the two six-input controllers and writes
`models/attachment.tflite` and `models/detachment.tflite`, each alongside a
`_scaler.json` giving the input and output normalisation the network was trained with.

```
python -m venv .venv
.venv/Scripts/activate
pip install -r requirements.txt
```

| Task | Command |
|---|---|
| Train and export the deployed controllers | `python -m learning.mlp26 --export` |
| Train all model variants | `python -m learning.mlp26 --skip-simulation` |
| Controller error on annotated measurement points | `python learning/eval_raw_points.py --model param` |
| Decision-space figure | `python learning/plot_x1_decision_space.py` |
| Decision-space figure from the data | `python learning/plot_action_space_data.py` |
| Body length from landmark data | `python learning/measure_body_length.py` |
| Regenerate processed data from the raw exports | `python learning/data_preprocess.py` |

Commands are run from the repository root — data and output paths are relative to it.
`eval_raw_points.py` trains the seed in `SEEDS` and reports the resulting error.

`learning/mlp26/simulation.py` is a reduced-order closed-loop simulation.

## Data

Kinematic demonstrations recorded from juvenile sharksuckers (*Echeneis naucrates*, body
length ≈14.8 cm) performing attachment and detachment in a still-water tank. Landmarks
were digitized from high-speed video at 25 Hz after acquisition at 250 Hz.
`data/raw/` holds the exports; `data/processed/` holds the sequences the pipeline trains on.
